# Telegram Assistant MCP

**[English](README.md) | Русский**

Ограниченный MCP-сервер для личных диалогов и групп Telegram. Он использует приватную пользовательскую сессию Telethon и проверяет OAuth access token перед каждым MCP-запросом. Восемь инструментов поддерживают чтение с лимитами, просмотр выбранных фотографий, необязательную внешнюю транскрибацию аудио и отправку текста/вложений с отдельным разрешением.

## Что умеет сервер

Сервер реализует восемь инструментов: `list_dialogs`, `get_history`, `search_messages`, `get_reply_context`, `view_photo`, `transcribe_audio`, `send_message` и `send_media`. В режиме `--read-only` регистрируются шесть инструментов чтения, а оба инструмента отправки отключены. История показывает наличие вложения, но не скачивает его. `view_photo` получает фотографию только по явному вызову для конкретного сообщения и возвращает нативный MCP image preview. `transcribe_audio` по умолчанию выключен. Если его отдельно включить, только выбранное голосовое или аудиофайл отправляется в OpenAI для транскрибации; длительность одного файла ограничена, а локальную месячную квоту в секундах можно включить отдельно. Перед включением прочитайте [настройку медиа-инструментов](docs/GETTING-STARTED.ru.md#инструменты-для-медиа).

`send_message` отправляет текст, а `send_media` — одно вложение или альбом фотографий/видео. Для обоих нужны одинаковые OAuth scope и разрешение политики для адресата; квоты отправки общие. `send_media` получает base64-данные от MCP-клиента, а не путь к файлу на сервере. Сервер проверяет содержимое и реальный размер, ограничивает один вызов 20 MiB и удаляет временные файлы после обращения к Telegram. Для больших MCP-запросов установлен отдельный предел 32 MiB; лимит ответа 48 KiB не меняется. Просмотр фото и транскрибация требуют scope на чтение; транскрибации также нужен включённый провайдер. Широковещательные каналы по умолчанию скрыты, поэтому сервер не даёт универсального доступа ко всем чатам и каналам Telegram. Перед выдачей доступа прочитайте [руководство по политике отправки](docs/SENDING-POLICY.ru.md).

## Что понадобится

- Аккаунт Telegram и постоянно доступный сервер/VPS.
- ИИ-агент, умеющий работать с кодом и сервером.
- Аккаунт или рабочее пространство ChatGPT, где вам разрешено добавить собственный MCP-сервер. Доступность и возможности зависят от тарифа, региона и настроек рабочего пространства; проверьте их в своём аккаунте и в [актуальной справке OpenAI](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt).
- Для удалённого подключения ChatGPT — публичный адрес с HTTPS и OAuth-провайдер. Подробный пример использует Auth0; аккаунт Auth0 нужен только если вы следуете ему. Сервер, домен и OAuth-провайдер могут стоить денег.

## Быстрый старт

Отправьте [короткую инструкцию](docs/START-HERE.ru.md) своему ИИ-агенту и попросите провести вас через настройку. Навыки программирования и ручной ввод длинных команд не нужны. Вы сами входите в аккаунты, вводите код Telegram и пароль 2FA, а также подтверждаете согласия. Секреты вводите только в защищённые поля или скрытые локальные запросы.

- Русский: [короткая инструкция](docs/START-HERE.ru.md) · [подробная техническая инструкция для агента](docs/GETTING-STARTED.ru.md) · [политика отправки](docs/SENDING-POLICY.ru.md)
- English: [beginner guide](docs/START-HERE.en.md) · [detailed technical setup for agents](docs/GETTING-STARTED.en.md) · [local send policy](docs/SENDING-POLICY.en.md)

В краткой настройке используется read-only режим. Включайте отправку только при необходимости и указывайте разрешённые адресаты. Не отправляйте и не коммитьте секреты и файлы Telegram session. Автоматические тесты используют заглушки и синтетические медиа вместо реальных аккаунтов. Не останавливайте работающий сервер без отдельного согласия пользователя.

## Разработка

Нужен Python 3.11 или новее. Тестовый набор использует подменные Telegram-клиенты, HTTP MockTransport, ASGI в процессе и синтетические аудио/изображения; он не входит в Telegram-аккаунт и не отправляет аудио провайдеру. В полном наборе также есть PTY-тесты, которым нужен обычный управляющий терминал. В lock-файле есть необязательный QR-рендерер; Docker-шаблоны нужно проверять на целевом Linux-хосте. Просмотр фото и remux OGG/Opus требуют `ffmpeg` и `ffprobe`; Docker image устанавливает их.

    python3 -m venv .venv
    .venv/bin/python -m pip install -r requirements.lock
    .venv/bin/python -m pip install --no-deps --no-build-isolation -e .
    .venv/bin/python -m unittest discover -s tests
