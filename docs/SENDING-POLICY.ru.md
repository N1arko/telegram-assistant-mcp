# Локальная политика отправки

**[English](SENDING-POLICY.en.md) | Русский**

Отправка текста и медиа по умолчанию запрещена. Локальная политика оператора — это
дополнительный технический барьер. Перед каждым вызовом ассистент отдельно
проверяет, действует ли пользовательская инструкция и подходит ли она адресату
и сообщению. Политика не описывает смысловые правила вроде «отвечай, только если
спросили о встрече». Редактор политики запускается локально и не доступен через
MCP.

## Файл политики

Храните рабочий файл политики вне репозитория. Каталог и файл должны принадлежать
текущему пользователю и быть закрыты от остальных. Перед проверкой места
сохранения редактор разрешает символьные ссылки в родительском пути, отклоняет
символьную ссылку на сам файл политики и пути внутри Git-репозитория, а
изменения записывает атомарно. Не добавляйте рабочую политику в Git.

Начните с `config/policy.example.json`. В нём нет разрешений и запретов; общий
предел — 5 отправок в минуту и 100 в сутки. Для каждого разрешения или правила
по умолчанию действует предел 1 отправка в минуту и 20 в сутки, длина сообщения
ограничена 4096 единицами UTF-16. Если одновременно подходят несколько
ограничений, действует самое строгое.

## Выбор адресатов и запреты

В политике версии 2 доступны такие селекторы:

- `peer` — один точный ID адресата;
- `all_human_dms` — личные диалоги с людьми; боты и собственный аккаунт исключены;
- `group_ids` — только перечисленные ID групп;
- `all_groups` — все доступные группы; это намеренно широкое правило;
- `first_contact` — возможность ответить на конкретное проверенное первое
  входящее сообщение от пользователя.

Broadcast-каналы, боты и собственный аккаунт не допускаются. Действующий явный
запрет для точного адресата имеет приоритет над разрешениями и селекторами. Если
нет действующего подходящего разрешения, отправка запрещена.

Для `send_media` используются те же grants `send_message`; формат политики и
OAuth scopes не меняются. Одного разрешения `first_contact` для отправки медиа
недостаточно. `send_media` принимает одно вложение или альбом из 2–10 фото/видео.
Подпись каждого элемента проверяется по тому же `max_chars`; квота списывает
отдельную единицу за каждое Telegram-сообщение в альбоме. Неудачная или
неопределённая отправка тоже расходует зарезервированную квоту. Неизвестный
результат проверяйте вручную; автоматически повторять вызов нельзя.

Поддерживаются фото JPEG/PNG, видео MP4/WebM, документы, аудио MP3, MP4/M4A,
WAV, WebM или OGG/Opus, голосовые OGG/Opus, GIF-анимации и статичные WebP-
стикеры. Суммарный размер одного вызова — до 20 MiB; фото — до
8 MiB и 12 мегапикселей; видео/GIF — не более 12 мегапикселей на кадр и до
пяти минут длительности; аудио и голосовые — до пяти минут. Стикер должен быть
статичным WebP до 512 KiB и 512×512 пикселей. MCP-клиент
передаёт вложение внутри вызова как base64; сервер держит его только во временной
закрытой папке на время отправки.

`first_contact` даёт только техническую возможность ответа. Вызов должен
содержать тот же ID сообщения в `reply_to`; сервис проверяет, что сообщение
входящее, отправлено этим пользователем и является самым старым из сообщений,
доступных сейчас в диалоге. При неполной истории или ошибке проверки отправка
запрещается. Удалённую на стороне Telegram историю проверить нельзя: проверяются
только доступные сообщения. Попытка ответа резервируется до отправки. Повторные
попытки блокируются; при неизвестном результате доставки его нужно проверить
вручную, автоматического повтора нет.

## Локальные команды

После установки проекта используйте `telegram-assistant-policy`, чтобы проверить
или изменить локальную политику. Замените показанные ниже примерные ID и время на
проверенные значения. Если не указывать `--expires-at`, разрешение будет
бессрочным.

```sh
telegram-assistant-policy --policy /secure/private/policy.json validate
telegram-assistant-policy --policy /secure/private/policy.json grant-peer \
  --peer-id 123456789 --expires-at 1893456000
telegram-assistant-policy --policy /secure/private/policy.json deny-peer \
  --peer-id 123456789
telegram-assistant-policy --policy /secure/private/policy.json revoke-peer \
  --peer-id 123456789
```

Для селектора используйте `grant-rule --selector` и одно из названий выше. Для
правила `group_ids` укажите `--peer-id` отдельно для каждой группы. Правило
`all_groups` действует на все доступные группы; перед его созданием внимательно
проверьте его охват. Команда `revoke-rule --rule-id` удаляет правило.
`allow-peer` снимает явный запрет для точного ID, но само по себе не создаёт
разрешение. Общие пределы меняет команда
`set-global-quotas --per-minute N --per-day N`.

CLI сообщает только общий результат и атомарно записывает файл с правами только
для владельца. Клиентам MCP управление политикой недоступно.
